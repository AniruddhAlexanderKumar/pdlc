02 / Eight sample activities

Your chapter notebook.

Choose a chapter and try its prompt. These exercises use the app’s curriculum and answer validation. Practice notes stay in this tab; they aren’t synced or awarded XP. Download them before closing or refreshing the file.

01Idea / Concept brief

Chapter objective

Capture the product idea and the problem it solves.

A clear problem gives you something specific to investigate.

Describe your idea in one sentence.

Imagine explaining it to a friend. Say what it does, not how it works.

Example
A booking page that helps independent tutors fill cancelled lessons.

Advanced guidance

Name the user, the job and the outcome. Leave implementation choices open.

Practice · Product concept

02Research / Research notebook

Chapter objective

Learn how people solve the problem today.

Separating assumptions from observations helps you decide what to test before investing.

What have you learned, and how do you know?

Separate a belief from something you looked up or observed. Independent evidence needs a traceable source. If you have none, record the assumption to test.

Example
Before interviews: “I think tutors want automatic reminders.” Classify this as a founder assumption.

Advanced guidance

Cite a dated, independently inspectable source for external evidence. Record limitations; the platform does not verify sources.

Practice · Research notebook

03Planning / Build roadmap

Chapter objective

Choose the smallest useful first version and plan the work.

A short feature list and a budget keep the first build achievable.

Put the essential features in build order.

Start with what a user absolutely needs. Move nice-to-haves out of the first version.

Example
Publish an open slot → claim the slot → send confirmation. Leave analytics out.

Advanced guidance

Order the critical path by dependencies and learning value. Record deferred scope in your MVP definition.

Practice · Prioritised feature list

04Design / Design brief

Chapter objective

Describe the experience from the user’s point of view.

A shared design brief lets you spot confusing steps before building them.

Walk through one person’s path from start to finish.

A user journey is the sequence of things someone does to get a result. Start before they touch the product.

Example
A parent gets a message, opens the slot, checks the time and confirms.

Advanced guidance

Include the actor, trigger, touchpoints, outcome and recovery path.

Practice · User journey

05Prototype / Prototype log

Chapter objective

Build a first version around one learning goal.

A small trial reveals blockers while changes are still affordable.

What should this first version help you find out?

A prototype is a rough version built to learn one thing. It need not be ready to sell.

Example
Try a clickable booking screen to see whether a parent can find the right time.

Advanced guidance

Identify the riskiest unknown, prototype fidelity and exit criterion.

Practice · Prototype plan

06Testing / Test report

Chapter objective

Compare what you expected with what really happened.

Observed results help you fix the right problem, not just the loudest complaint.

Give a tester one realistic task to try.

Tell them the goal rather than the clicks. Pick someone similar to your target user.

Example
Ask a parent to book next Tuesday’s free slot. Watch without coaching.

Advanced guidance

Specify tester segment, environment, test data and observation method.

Practice · Test scenario

07Launch / Launch plan

Chapter objective

Decide who will get the product, when and at what price.

A release checklist and a measurable goal give you a useful first week.

How will your first customers hear about it?

A go-to-market plan names an audience, a place to reach them and a clear invitation.

Example
Show the booking flow in a tutor association newsletter and invite readers to try one slot.

Advanced guidance

Specify channel, message, asset, owner and conversion event.

Practice · Go-to-market outline

08Improvement / Iteration brief

Chapter objective

Turn feedback into the next development cycle.

Returning to an earlier chapter lets you test a change without losing what you learned.

What will you change in the next version?

An iteration is another build-and-learn cycle. Pick one change and how you will tell whether it helped.

Example
Try a clearer time label and repeat the booking test with new participants.

Advanced guidance

State the intervention, success metric and next experiment.

03 / Complete workspace

Run the real app locally.

For accounts, saved drafts, reviews, costs and the full journey, download Solution-Velocity-Local.zip from the conversation files. Extract it and open a terminal in the folder containing package.json. With Node.js 22.12 or newer installed, run:

npm ci
npm start

Open the address printed in the terminal. Installation needs internet once; Docker and an Arena sandbox are not required. This starts a new local workspace, not a copy of any hosted account.
