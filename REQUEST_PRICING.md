# Request-access pricing

The Request Access page submits plan, editor count and billing frequency with the applicant details. `packages/shared/src/pricing.ts` is the versioned pricing engine for the live preview and backend. It uses integer cents; the API validates the plan/count combination and calculates the quote itself. The request stores a JSON pricing snapshot, including the calculation version, so the original request is not rewritten by a later price change. Enterprise totals and discounts are custom rather than invented. Existing older clients and historical requests remain valid without a quote.

System administrators can view the original request, record statuses and internal notes, and save a separate proposed quote. Proposal/status changes are recorded in `access_request_events`. The applicant must be contacted about changes; saving a proposal or marking a request approved does not send a message, charge money, activate a subscription or provision a workspace. The contact link opens the administrator's email client.

There is no existing payment provider, checkout, webhook handling, subscription renewal, seat enforcement, invoice/tax system, credit accounting or AI allowance implementation. These are not represented as operational. Before building payment activation, select and configure a provider, verify amount/currency and applicant consent server-side, use signed idempotent webhooks and provision only after confirmed payment. Do not turn the request form into a charge. No payment credentials or card details are stored here.

## Education requests

Education is a separate category and calculation engine (`packages/shared/src/education-pricing.ts`); Commercial pricing remains unchanged. Individual Student is $2 per month for one student with the standard 0/5/10/20% period discounts. School Cohort is $1.50 per student per month for 10–100 students; `COHORT_PERIOD_DISCOUNTS` is initially zero for every period and can be changed deliberately with a pricing-version change and tests. Education Enterprise is custom; no monetary amount or discount is guessed. Longer periods are calculated in integer cents. The UI switches to Enterprise when a cohort count exceeds 100; custom requirements can use Enterprise at smaller counts too.

The server strictly validates selected plan, billing period, counts and required plan-specific applicant details. It recomputes and stores the versioned `education_pricing_snapshot` and `education_details`; incoming price fields are rejected. System admins can record a separate proposed Education quote and status while retaining the original and audit event. A proposal is not sent automatically: the admin must communicate and obtain agreement separately. Renewal date is not known before activation. None of this creates an Education subscription, collects payment, activates access, or implements student invitations, licence assignment/reassignment, cohorts, teachers, education roles, paid-seat enforcement, taxes, invoicing or renewals. Approval is a request status, not provisioning.
