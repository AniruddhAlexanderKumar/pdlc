# AI Assistant: implementation and operating limits

## What is available

The authenticated `/assistant` interface is in the main navigation (including mobile and collapsed navigation). Personal conversations, messages and proposed actions are stored by user and workspace. Conversation project context is fixed on creation; start a new conversation to choose a different project. Users can search their conversation titles and their own messages, rename, delete or clear conversations. Project deletion cascades to its conversations; completed action audit records remain until their workspace or actor is deleted. Temporary demo users see the navigation entry but cannot use the assistant.

Workspace project lists, project summaries and outstanding issue lists are deterministic and based on the selected workspace project; they link back to recorded issues and do not use model credits. Help answers quote relevant published articles and link to them; audience checks apply, and historical assistant answers that reference an unavailable or subsequently changed guide or issue are redacted on retrieval. For other questions, an explicitly enabled AI provider can generate a response from a bounded set of relevant issue summaries in the selected project, matching permitted published help and the last four user questions from that conversation. Model text is labelled as an interpretation. Previous assistant replies are not fed back into the model, avoiding propagation of help content that later becomes unavailable. The app does not yet store engineering requirements, documents, verification evidence, milestones or Education-specific roles; the assistant cannot verify or retrieve them.

The supported write proposals are `Create a new engineering project called <name>`, and, with project context, `Create a task called <summary>` / `Create a task for <summary>` and `Set task <PROJECT-123> status to <Open|In Progress|Done>` and `Set task <PROJECT-123> priority to <Low|Medium|High|Critical>`. The action shortcuts prefill these commands so users can enter their own details. Status and priority proposals show the old and new value and fail if the title or the selected field changed before confirmation. They create pending proposals, not records. The explicit confirmation endpoint rechecks workspace membership, current role and project, serializes execution and records the actual result; retries are idempotent. Project creation is restricted to workspace owners/admins; task creation uses the existing workspace-member policy. No model output can invoke a tool or choose an arbitrary API. Other write and destructive actions are not supported. Commands use deterministic matching rather than giving the model permission to operate arbitrary endpoints.

## Model configuration and token accounting

AI generation is **off by default**. Set `ASSISTANT_AI_ENABLED=true` on the backend and configure `ASSISTANT_PROVIDERS` as a JSON array of up to four objects with `name`, `baseUrl`, `model` and `apiKey` fields, in fallback order. Alternatively, omit `ASSISTANT_PROVIDERS` and configure AI/ML API, OpenRouter and/or Gemini as described below; when neither is configured the existing `AI_BASE_URL`, `AI_MODEL` and `AI_API_KEY` fallback is used. Only HTTPS provider URLs or local loopback HTTP URLs are accepted. Do not commit keys. Keep secrets in the hosting platform's protected environment and configure `APP_URL` correctly. Questions, selected relevant issue summaries and matching published help may be sent to the selected provider; the interface warns users not to include secrets. Configure provider retention and privacy policies before enabling.

### Google AI Studio (Gemini)

Revoke/rotate any keys shared in chat or exposed elsewhere. Store replacement keys only in protected backend environment settings. Set `ASSISTANT_AI_ENABLED=true`, `ASSISTANT_GEMINI_MODEL` to a text model currently supported by your Google AI Studio project, and `ASSISTANT_GEMINI_API_KEY_1` through `_4` for up to four keys. At least one key and a model are required. The assistant uses Google's [OpenAI-compatible endpoint](https://ai.google.dev/gemini-api/docs/openai); Gemini key slots are tried in order under the existing fallback and accounting rules. `ASSISTANT_PROVIDERS` takes precedence if set. Without it, AI/ML API (when configured) is first, followed by OpenRouter and then Gemini; if none is configured, the existing `AI_*` fallback applies. Never put secrets in a browser bundle, commit or shared logs. Verify Google project billing, quotas, access, model availability and data-retention terms before enabling. Different keys may share a project quota, so fallback does not guarantee additional quota. Successful live Gemini connectivity is not verified by the local test provider.

### AI/ML API

To use the provider from the supplied example, revoke and rotate the exposed key and set the replacement as `ASSISTANT_AIMLAPI_KEY` in the protected **backend** environment. Set `ASSISTANT_AI_ENABLED=true` and grant the workspace an assistant token allowance. `ASSISTANT_AIMLAPI_MODEL` defaults to `openai/gpt-5-5`, and may be overridden with a compatible text model available to that account. The provider uses `https://api.aimlapi.com/v1/chat/completions`; it does not expose credentials to the browser. It is first in the configured order, followed by OpenRouter and Gemini when present. Explicit `ASSISTANT_PROVIDERS` overrides these settings. The configured provider names are displayed in the assistant so users can see where their questions and relevant project/help context may be sent. Review the provider's terms, data handling, model access, rate limits and pricing before enabling; the existing token allowance is not a spending cap. This is a single-provider response with fallback, not simultaneous model aggregation; it cannot guarantee better answers. Live connectivity and the selected model's access have not been verified.

### OpenRouter

Rotate any key exposed in chat. Configure the replacement in the protected backend environment as `ASSISTANT_OPENROUTER_KEY`, set `ASSISTANT_OPENROUTER_MODEL` to a compatible OpenRouter model available to the account, and enable the assistant and grant a workspace allowance. The endpoint is `https://openrouter.ai/api/v1/chat/completions`. OpenRouter is tried after AI/ML API and before Gemini; configured `ASSISTANT_PROVIDERS` overrides this order. OpenRouter and its upstream model provider may receive the question and permitted context; review privacy policies and costs. Model access and live connectivity have not been verified. A fallback is a separate provider attempt, not a combined multi-model response.

A global system administrator can grant explicit provider-token credits under **Admin console → Assistant token allowances**. Each new workspace starts at zero; there is no automatic free or unlimited model allowance. Before each provider attempt the service atomically reserves a conservative token budget from that workspace; on a successful response it settles against the provider's reported `usage.total_tokens`. Provider 401/402/403/429 responses release the reservation before trying the next configured provider. Transport failures, server errors or malformed/unaccounted responses retain the reservation as `uncertain` for administrator review because the provider may have incurred a charge. Attempts, model, user and token totals are recorded; no prompt, response, key or provider error body is written to the usage log. A provider-reported overrun is charged even if the workspace balance becomes negative, blocking later reservations. Reservations remain reserved if the process terminates mid-request; operators must reconcile them against the provider and, if appropriate, grant a compensating amount. The admin screen shows recent attempts. There is no automatic reconciliation or settlement for abandoned reservations.

These are explicitly granted token allowances for this assistant, **not** a subscription, a payment purchase, plan entitlement, dollar value or the application's other AI features. The legacy graph, Help and voice AI routes do not yet share this ledger. There is no subscription billing, payment integration or extra-credit purchase flow. Do not describe the token balance as a paid subscription balance or enable other AI features assuming this ledger limits them. Process-local per-user rate limits require shared or edge rate limiting for multi-instance deployments.

## Safety and current limitations

All conversation and project queries are scoped server-side to the authenticated user and active workspace. Help articles are checked against the caller's current role and publication status. Provider credentials remain on the server. Model output is treated as untrusted advice and cannot execute writes; a user must confirm each supported proposal. Prompt injection can still influence natural-language advice, so users must review results. Owners/admins and members are the only workspace roles; institutional and student separation, document permissions, attachments, OCR, semantic document search, voice conversation, response streaming, model-led tools and educational entitlements are not implemented. No record source may be inferred to exist merely because the model discusses it. The interface renders Markdown as text/formatting without active AI-generated links or images and displays server-selected source links separately.

Deploy migrations `020_assistant`, `021_assistant_status` and `022_assistant_priority` together with backend and frontend code. The `021` and `022` rollbacks intentionally fail if their new action audit records exist; it never deletes them automatically. Test only on a disposable database: `ASSISTANT_TEST_URL=http://localhost:4000 ASSISTANT_TEST_DB=postgres://... node apps/server/scripts/assistant-smoke.mjs` assumes the local test API has two configured test providers, one returning 429 and the other a fixed response with usage. The additional `assistant-status-smoke.mjs` and `assistant-environment-smoke.mjs` check actions, isolation and unavailable voice models against a disposable server/database (configure the voice endpoints to unused localhost ports for the environment smoke). Never point these tests at production. Also run `npm run typecheck`, `npm test`, `npm run build`, and permission/responsive checks. See `SECURITY.md` for password-reset SMTP configuration added in the same release.

## Other AI features

The product insight, graph interpretation and voice routes use their own separately configured legacy model paths; they do not use assistant providers or the assistant token allowance. The unused raw `/api/ai` endpoints are restricted to system administrators. Voice processing no longer substitutes invented products, costs, materials or tasks when its model is unavailable: it returns an error. Model-generated voice drafts may still be inaccurate and must be reviewed; unknown required numeric fields may appear as zero. Voice import creates a project, so only owners/admins may import. The transcript is sent to the separately configured voice provider.
