# Solution Velocity P0: remediation and operational handoff

Status: implementation and isolated tests only, not a production deployment or completion of the operational security/recovery work. The repository contains other pre-existing uncommitted work. Do not deploy the whole tree without separating and reviewing it. No production data was accessed or changed.

## Database transaction review

- Product create/update and task create/update execute through `mutate`; their analytics now use the same transaction, with a savepoint so an analytics failure does not abort the business transaction. Voice import does the same. An event written inside the savepoint is committed only with the business transaction; best-effort telemetry may still be lost if its insert fails. Authentication and browser-event analytics calls are outside their business transactions.
- The reviewed transactions in auth, workspace/profile, catalog, projects, Teamwork Graph, help, admin, assistant, AI allowance accounting, demo cleanup and external reviews use their transaction for database work or pass it to database helpers. External-review `event()` calls are outside transaction callbacks; in-transaction review events are written with `trx`. This is a source review and targeted test, not a formal proof against every possible helper or future call.
- A distinct existing risk remains: external-review revocation updates the review and then records its security event in a separate operation. An event-write failure can yield an error after revocation has committed. Address separately with an explicit security-audit availability policy; do not silently change revoke behavior without deciding whether audit failure should ever block revocation. Non-voice create operations also lack general idempotency keys; after an uncertain response, check existing records before repeating them.

## Voice integrity and rollout

Migration `024_voice_import_integrity` adds receipts and explicit one-to-one links with database-enforced status-only synchronization. It does not infer or backfill associations. Deleting either record removes the link, not the surviving record. Non-empty milestone tags are rejected rather than silently dropped; milestones must be recorded separately. Titles, descriptions, priorities and other fields are independent; synchronization does not award completion XP on the issue-update path. Opposite-direction concurrent updates can deadlock; the transaction rolls back and the API returns a retryable 409. Read current state before retrying a status edit.

Preview and import use the same validator, sharing manual product, project, issue and task field schemas as well as canonical question validation and synchronized product-field bounds also enforced by manual answer entry. Voice import accepts only `{ requestId, draft }`; the key is scoped to user/workspace and must be reused with the same normalized draft. A changed draft with the same key conflicts; a previously imported and subsequently deleted product/project is not recreated. Browser retry recovery stores the submitted draft and key in session storage in the current tab until confirmation; it is not durable across browser sessions or other devices. Storage failure blocks the import. Starting over discards the retry key and may create another import, so first verify whether the prior one completed. Session storage may contain sensitive draft content: use a trusted device and close the tab after finishing.

Coordinate frontend and backend deployments: old clients must refresh before voice imports and will receive an explicit refresh-required error. During a mixed-version rollout, temporarily pause voice imports until all application instances and clients are updated; old server instances do not enforce the new mapping/idempotency contract. Migration 023 is another pending local change and must be reviewed independently before 024. The migration's `down` removes the new receipts and links; it is not a safe lossless production rollback after new imports. Do not roll back without an approved recovery plan and verified backup. New application code requires the new tables; coordinate schema and application versions. The simulated fixture 023-to-024 test first removed 024 from a restored fixture, then reapplied its migration function directly; it was not a migrator-driven upgrade or a production migration run.

## Credential incident: action required by authorized provider administrators

The following credentials were exposed in conversation and must be treated as compromised, irrespective of the scan result: four Google AI Studio credentials, one AI/ML provider credential, and one OpenRouter credential. Values are deliberately omitted here. No provider administration was available; none has been confirmed revoked, replaced or rotated.

For each provider/account, an authorized administrator should:
1. Identify affected key IDs via the provider's own console, restrict or revoke each compromised key immediately, and record non-secret key identifiers, actor and timestamps in the incident system.
2. Inspect provider usage, spending, audit logs and project permissions around the exposure; investigate anomalies and set appropriate limits and alerts.
3. Create minimum-privilege replacements if needed, store them only in the approved server-side secret manager, and update authorized runtime integrations without printing values or committing them. Coordinate changes and avoid unnecessary service interruption.
4. Verify revocation and replacement using provider-admin evidence and a controlled, authorized application health check; never test the compromised values. Confirm secret redaction in CI, deployment configuration, and logs.
5. Record owner, status, evidence location and residual risk per credential. Treat other credentials as exposed if review finds them, and follow the same process.

A limited pattern scan of 287 working-tree/build/fixture-log text files and 215 reachable local Git blob objects found no matches for selected Google, OpenRouter, OpenAI-style, GitHub, AWS access-ID and private-key formats. It is not an exhaustive secret scan; it does not establish absence of other formats or earlier chat, remote-only refs, CI artifacts, deployment environments, third-party logs or provider exposure. No production logs or deployed browser assets were available. Repeat a properly configured secret scan against the authorized production sources and artifacts, without publishing matched values.
