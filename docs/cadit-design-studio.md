# CADit Design Studio integration

The existing authenticated `/designs` navigation opens the external CADit editor, using the [official embedding example](https://github.com/cookiecad/cadit-embed-example). The existing experimental sketches and conceptual diagrams remain available at `/designs/sketches` and `/designs/diagrams`. The temporary demo does not expose the editor. No CAD engine, partner authentication, database changes or project-file storage are added here.

The iframe receives an `init` message only after `ready`; incoming messages must match both the exact CADit origin and the current iframe window. STL export can be initiated either inside CADit or with the host request button. A received nonempty Blob is offered as a browser download, not stored on the server. The status confirms receipt, not that the operating system saved a file. Files are not validated as engineering-ready STL models. The page warns before leaving once the editor is ready, but cannot detect the editor's actual unsaved state.

The iframe is a third-party service: CADit receives the browser request, including network metadata, and any information a user enters into CADit is governed by CADit's practices. Solution Velocity does not send its session, project details, or partner token in this integration. A CADit account or other permissions may be required for CADit features; this integration does not authenticate the user to CADit. Work is not linked to any Solution Velocity project or persisted by Solution Velocity. Export an STL and use CADit's own saving options where available before leaving.

## Deployment and external requirements

CADit's README states that **all hosting origins must be registered in CADit's allowlist**: production, staging, preview, local development and custom domains. Contact CADit through its website or the example repository to arrange this. Registration has not been verified for any Solution Velocity domain or the Arena preview. The example also documents public key and issuer requirements for optional partner authentication, which is deliberately not implemented here. The Express CSP permits framing `https://app.cadit.app` while retaining the app's existing `frame-ancestors 'none'`; any separate CDN or hosting CSP must also permit that exact `frame-src`. CADit's own framing policy and availability remain outside our control. A loaded iframe alone is not evidence of a working integration; the UI waits for CADit's `ready`, and displays a timeout if it never arrives. A late valid `ready` can recover the session.

## Verification

Run `npm run typecheck`, `npm test`, `npm run build`, and the synthetic browser smoke in `apps/web/scripts/cadit-browser-smoke.mjs`. The smoke intercepts the CADit URL with a controlled fixture and tests real cross-origin `postMessage`, origin/source rejection, init, export/download, bad payload handling, timeout, navigation warning and responsive layout. It does **not** establish real CADit connectivity or prove domain registration. Test real connectivity only after CADit approves the hosting origin; do not include production credentials in testing.

## Live investigation and release gate (2026-11-07)

- The sandbox can resolve `app.cadit.app` and opens TCP port 443, but its TLS handshake ends with `SSL_ERROR_SYSCALL` before receiving an HTTP response. A browser in the same environment reported `net::ERR_CONNECTION_CLOSED`. The sandbox also cannot complete TLS to the Solution Velocity domain, while GitHub succeeds; outbound access is restricted here. This establishes a network-path limitation in this environment, not a CADit domain rejection, an iframe-policy rejection, or a CADit outage.
- An independent page-fetch service rendered the public CADit URL and its “Send to Solution Velocity” label. This confirms the URL can be reached from that service, not that this application's iframe, handshake, 3D editor or export works. The same service rendered CADit's official GitHub Pages demo iframe, but reported “Error creating WebGL context” and the demo status remained “Waiting for CADit to load”; this is not a successful live integration test. The official example inspected was commit `7587990317caee7b7f30f55a9c08e47e45b9afbd`.
- The implementation matches the published `ready`, `init` with `features: ['export']`, `get-stl` and `export-stl` envelopes. CADit says every hosting origin must be allowlisted; approval of the actual production, staging and preview origins is unknown. No partner authentication is implemented. CADit may require additional account/feature permissions, which need confirmation by CADit.
- The app's Express policy sets `frame-src 'self' https://app.cadit.app` and retains `frame-ancestors 'none'` plus Helmet's `X-Frame-Options: SAMEORIGIN`. Those latter headers govern embedding **Solution Velocity**, not its ability to embed CADit. Express removes `X-Frame-Options` and relaxes `frame-ancestors` only for the separate public `/product-designer.html`. `_headers` supplies that standalone document's policy for hosts that honor Cloudflare Pages `_headers`; the example nginx and Caddy configs do not add CSP. We could not observe the actual deployed response headers from this sandbox or verify separate CDN/proxy policies, nor CADit's live `Content-Security-Policy`/`X-Frame-Options` response headers. Multiple CSP headers are enforced together; any additional restrictive policy can still block the embed. `referrerPolicy="no-referrer"` is set on the iframe; whether CADit relies on referrer information is unverified.
- The iframe remains mounted but is covered until an origin- and source-verified `ready` signal arrives. A 20-second timeout shows an unavailable panel and leaves retry, sketches and diagrams accessible. A later valid `ready` can recover. A `ready` signal is only protocol readiness: it does not prove WebGL, editing or export works. Browsers generally do not expose cross-origin iframe load failure details to the parent, so the panel does not claim a specific cause.

### Before any merge or deployment

1. Ask CADit to confirm registration of the exact production and staging origins (scheme, hostname and port), plus the particular preview origin if it is to be used. Confirm embedding and unsigned export permissions and any account, WebGL or browser requirements. Do not send credentials or design data to support.
2. From an authorized browser and approved staging origin, inspect the actual host and iframe **network response headers**, including all CSP `frame-src`/`child-src`/`default-src` policies and CADit's `frame-ancestors` and `X-Frame-Options`, redirects, TLS and browser console security messages. Verify applicable CDN, hosting and proxy settings; do not weaken `frame-ancestors` for the main application. Check browser network and console without recording tokens or private content.
3. Using a disposable design without sensitive data, verify the real iframe renders and can interact, the exact-origin/source `ready` leads to the documented `init`, a real shape can be exported as STL, and the downloaded bytes open in an independent STL viewer. Verify the deployed origin, browser, operating system and date. Repeat the product-designer and sketch regression checks. Fixture tests and the sandbox page fetch do not satisfy this gate.
