# Part 3: application audit and initial document foundation

**Status: incomplete.** This is not a CAD application and does not pass the Part 3 acceptance gate. The optional interface in this increment is a real, read-only sketch-source inspector and document manager, not a sketch editor, viewport or modelling system. It is accessible only when the already-existing server flag `CAD_NATIVE_EXPERIMENTAL` is explicitly enabled. The API remains disabled by default. No production deployment or database changes were made.

## Architecture, permissions and data

- The server already applies migration 026 during normal migration boot even when the API is disabled. It stores workspace-scoped source JSON in append-only revisions, not feature graphs/B-reps/meshes. Its `down` destroys all CAD documents and revisions. No new migration or rollback was introduced or run against production.
- The existing route authenticates and scopes every query to the current workspace; create is available to workspace members, and only the creator or workspace owner/admin can edit/archive/restore. The API validates source, solves it, uses expected revisions and row locks, and returns 409 on competing writes. Server access controls are authoritative; the UI does not grant permissions. Lists and details use `Cache-Control: no-store`.
- The UI discovers availability by requesting the existing authenticated list route; a 404 hides the Design Studio link. Direct navigation shows an unavailable/error page when disabled. Demo access is hidden and already blocked by server middleware. Query keys include workspace ID. Creation failure explicitly warns that a lost response might have committed; users should refresh before retrying. This is not interrupted-save reconciliation.
- The dashboard shows the most recent 200 records per API list, with filters over loaded data, revision numbers and creator/admin versus read access. Document inspection shows actual persisted entity/constraint records and makes no claim of solver state. All displayed actions have real handlers; unsupported modelling actions are not displayed.
- Files changed: `apps/web/src/pages/CadDocuments.tsx`, `DesignStudio.tsx`, `main.tsx`, web package manifest and lockfile, plus two disposable-browser test scripts and this handoff. Screenshot `03-cad-document-foundation.png` is an actual local browser capture using explicitly generated fixture data; it depicts the **document foundation only**, not a working editor. No third-party CAD/renderer dependency was added; the web workspace gained a type-only dependency on SV's own `@sv/cad-core` contracts.

## Unmet acceptance and next sequence

No browser rectangle drawing, zero-DOF verification, 3D extrusion, parametric edit, revolution, Boolean modelling, feature history, undo/redo, autosave/recovery, export or CAD-assistant acceptance flow has been demonstrated. The Part 3 workspace layout, resizable panels, editor, 3D viewport and subsequent stages remain unimplemented. Finish and validate a safe 2D editor and persistence/conflict/recovery contract before connecting modelling operations; separately close the Part 2.5 mathematical/geometry gaps and validate every exposed operation. Review existing migration 026 and backups before any separately authorised production rollout. Previously exposed provider credentials remain compromised unless their providers confirm rotation; no such credentials were used here.
