# Experimental native sketch editor — Part 3.1 handoff

**Status: partial; the complete Part 3.1 acceptance gate is not met.** This is a real but restricted XY sketch editor, not a production CAD system. It is behind the existing `CAD_NATIVE_EXPERIMENTAL` API flag (default false), is not available in the temporary demo, and must not be used for engineering decisions. No 3D operations were added.

## Implemented and tested subset

- `apps/web/src/cad/SketchEditor.tsx` edits actual `Sketch` entities, not screen-only geometry. An SVG canvas provides a configurable grid, axes, origin, coordinate snapping, zoom, selection, shift multi-selection and drag movement. Point, line, circle and rectangle tools use persistent UUIDs; the rectangle uses four lines plus four coincidence and four horizontal/vertical constraints. Construction and visibility toggles, deletion with attached-constraint removal, a selection list and properties are functional.
- Endpoint/center snaps create real coincident constraints when there is a supported point reference. Midpoint, origin and grid snaps change position only; no unsupported midpoint or fixed constraint is implied. Movement is unconstrained pointer movement followed by an actual solve and may be pulled back by existing constraints. Position and visible dimensions are shown in mm (display rounded to 0.001 mm; model data is not rounded to that display precision).
- Supported UI constraints include horizontal, vertical, parallel, perpendicular, equal line length, a selected first line's end coincident with the second line's start, fixed start/center or anchor to origin, driving line length and circle/arc radius. Constraint additions, deletions and dimension edits use the existing `commitSketch`/`solveSketch` pipeline; invalid or uncertain candidates keep the previous valid snapshot. Solver status and DOF come from the actual solver, including its limitations and non-localized redundancy warning. Conflicting IDs are indicated where the solver provides them. Selected line/point/circle information and constraint records are shown.
- Browser undo/redo uses immutable source snapshots including constraints, not screenshots. History is rebased to the latest acknowledged API revision so undo after a save is a new edit. It is session-only; undo history is not persisted across navigation/reload.
- `useSketchDocument.ts` implements explicit save and 1.2-second debounced autosave, one request at a time. The displayed saved state follows a server response or a confirmed read of a matching next revision. Revisions are checked by the server. A lost/failed response triggers a server read: matching name and geometry at the next revision are treated as an equivalent confirmed save; a different newer revision becomes a conflict. Transient failures are retried up to a bounded limit; local edits are never intentionally replaced by a stale server version. There is no server-issued idempotency key, so content equivalence does not prove which client caused an identical revision.
- Unsaved sketches are stored in **sessionStorage** under user/workspace/document-specific keys for same-tab refresh recovery; the editor asks before recovering or discarding. A stale draft can be downloaded before deliberately loading the server version. Recovery JSON has no import/merge UI. Storage availability and browser policy are not guaranteed, and sessionStorage recovery after tab closure or browser restart is not guaranteed. Sketch data stored there is not encrypted and is accessible to scripts on the same origin; do not use on an untrusted device. The API remains the authoritative persistent store. Navigation, sign-out and workspace switching warn before leaving unsaved work.
- The real CAD dashboard opens the editor using the existing workspace-scoped API; rename is performed by the existing versioned save. Unauthorized members can inspect but editing controls are disabled and server permissions remain authoritative. No document schema change or new migration was introduced. Existing migration 026 still applies at normal boot and its down migration is destructive; it was not run against production.

## Verified behavior

- Baseline at `affbb5c`: 103 tests and full typecheck passed. Local branch was fast-forwarded only after its complete staged tree matched the existing remote tree exactly; no working files were discarded.
- Browser E2E (`apps/web/scripts/cad-sketch-editor-smoke.mjs`) created a document via Design Studio; dragged a 10×20 mm four-line rectangle; applied an origin anchor and actual 10/20 mm driving length constraints; observed solver-reported zero DOF; changed width to 12 mm while preserving 20 mm height; tested undo/redo; inspected persisted geometry and 11 actual constraints; saved, returned to the dashboard, reopened and refreshed. It tested a deliberately conflicting constraint, same-tab recovery after an aborted PUT, automatic retry, loss of an already-committed response (no duplicate revision in that case), unauthorized workspace-member edit denial, and two-tab 409 conflict with local edit preserved. The screenshots below come from this real browser test with disposable fixture records.
- Browser tools E2E (`cad-sketch-tools-smoke.mjs`) exercised point, line, circle, endpoint coincidence and midpoint snaps, point movement, radius constraint, construction and visibility toggles, deletion and undo/redo. Existing CAD document browser and conceptual Design Studio browser smokes passed. Disabled-feature browser test verified API 404 and hidden navigation. Existing CAD and diagram API smokes passed on a disposable PostgreSQL fixture, including authentication, cross-workspace isolation, concurrent revision conflict, archive/restore and reconstruction after an API restart. A smoke initially used the old inspector link and was updated for the editor route; an initial tools assertion used too-tight pointer-coordinate tolerance and was adjusted to 1e-8 m. No production database was used.
- Final workspace typecheck, 105 tests (43 CAD core, 37 shared, 15 server, 10 web), build and `git diff --check` passed. Existing Vite chunk-size and Tailwind sourcemap warnings remain. No third-party CAD library, geometry kernel, solver or rendering engine was added.

## Remaining limitations / acceptance gaps

Arc creation and polyline tools, graphical constraint indicators beyond dimensions, arbitrary endpoint selection, inferred horizontal/vertical alignment, direct coordinate entry, contextual menus, resize/collapse panels, all supported solver dimension/constraint families, and full keyboard/accessibility coverage are not implemented. Some solver families are tested in core but deliberately not exposed. Circle creation/radius and existing arcs can be displayed; arcs cannot be created here. The small tutorial reports detectable state but is not a complete verified guided lesson. UI performance/large-sketch responsiveness and exhaustive adversarial numerical testing are not measured.

The solver remains experimental: rank/DOF are local numerical estimates, indirect conflicts can be uncertain and redundancy is not localized. The UI must not imply global uniqueness or production robustness. Autosave/recovery does not guarantee recovery after tab/browser closure, cross-device recovery, encrypted drafts, conflict merging or an exactly-once protocol. No real-time collaboration, 3D, new B-rep algorithm, assembly, import or external CAD dependency was introduced. Full Part 3.1 acceptance requires the missing interactions, recovery guarantees and broader regression/security/accessibility evidence; the rectangle flow alone does not close that gate.
