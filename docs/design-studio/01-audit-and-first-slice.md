# Design Studio: audit and initial slice

## Audit
The current React/Vite app has an authenticated workspace layout; Express checks active workspace membership and uses PostgreSQL/Kysely migrations. Products and projects are separate workspace-scoped records; issues belong to projects. Requirements, engineering decisions, verification, GitHub integration and design documents do not currently exist as first-class records. Demo sessions have restricted APIs. A substantial unrelated working tree must be preserved and reviewed separately. The existing CAD research and licensing approval gate remain unchanged.

The installed `@xyflow/react` 12.12.0 declares MIT licensing and is already used for Teamwork Graph; it can be evaluated for later editing. React declares MIT. A bounded SVG/form editor avoids adding a second canvas library for the initial slice and is keyboard operable. It is not an infinite canvas, full graph editor or UI/UX tool. Broader evaluation must cover maintained vector rendering, mobile/keyboard access, import/export security, performance, licensing and accessibility before selecting further dependencies. OCCT and solvers remain subject to the existing CAD gate; none is added here.

## Initial vertical slice
An authenticated, workspace-scoped design dashboard and one structured **conceptual diagram** type, with optional links to an existing product and/or project in the same workspace. Users create editable labeled boxes and directed connections, save structured versioned source, reopen and restore an earlier saved revision as a new revision. All workspace members may read; the creator and workspace owners/admins may edit. Optimistic concurrency rejects stale saves; simultaneous sessions are not real-time collaboration or an exclusive lease. No project task or requirements/test linkage is implied. SVG preview is derived from source, not the authoritative document.

This is deliberately not the whole Stage 1 or Stage 2. Asset uploads/libraries, templates, named versions, comments, sharing, comparison, autosave, task/graph links, diagram export, richer interaction, UI/UX and AI editors, and CAD are not implemented by this slice. No unsupported create option or control should be exposed. Design history must not be silently overwritten and stale editor content must remain available to copy on conflict.

## Security and data constraints
All reads and writes use the active workspace from authentication; create validates product/project references under that workspace. Revision saves lock the document row, validate source and expected revision, and atomically append a revision before advancing the head. Each document and revision is bounded; diagram labels are rendered as text rather than HTML. No image uploads or untrusted executable code. Demo access is unavailable until explicitly supported. A draft in an unsaved tab can be lost; users must save explicitly. Deployed migration version and production backup remain unverified; migrations are not run against production by this work.

## Migration, verification and deployment
Migration `025_design_studio` adds documents and append-only revision tables without backfilling or changing products/projects. It follows the existing pending migrations 023 and 024. The code and schema must be deployed together. Its down migration drops all design data and is **not** a lossless rollback; obtain and verify an appropriate backup and approved recovery procedure before deployment. Production migration state and backup coverage are unknown.

Isolated tests performed: schema/unit validation; a fresh local PostgreSQL instance through migration 025; API creation, product/project workspace checks, cross-workspace denial, creator/admin permissions, concurrent stale-save conflict, revision restoration; structured source reopening after API process restart; and Chromium interaction for create, drag, edit, connect, save, reload, conflict with retained unsaved changes and restore. The browser test used a disposable database/API, not production. Design history stores complete bounded source snapshots; restoring creates a new revision rather than deleting history.

Full roadmap acceptance tests A–F do **not** pass with this slice: no multi-screen prototype, record-linked components/requirements, image/asset graphics, comments, AI-generated drafts, CAD or exports are implemented. No real-time collaboration, autosave, local crash recovery, archive, search beyond the 200 most recently updated documents, named versions, or per-document sharing is provided. Browser/tab crashes or expired sessions may lose unsaved work; save explicitly. A revision-based optimistic conflict is not an exclusive single-writer lease. The current confirmation guard covers navigation, workspace switch and sign-out, but cannot guarantee recovery from every interruption.

## Preliminary library evaluation (not dependency approval)
Registry metadata checked 2026-11-05; latest registry versions are not necessarily the versions this application would use. Recent registry modification alone does not establish maintainability, security or suitability. Check full license texts, transitive dependencies, provenance, changelogs and accessibility before adoption.

| Candidate | Registry license / maintenance signal | Fit, accessibility and integration cost |
|---|---|---|
| Browser SVG + React | Existing React 19.3.1 declares MIT; no new rendering package. | Appropriate for the bounded first slice and text can be exposed semantically; requires hand-built editing, accessibility and layout. Large documents need measurement. |
| [React Flow / XYFlow](https://github.com/xyflow/xyflow) | Installed 12.12.0 declares MIT; registry latest 12.12.1, metadata modified 2026-11-04. | Existing graph dependency and a candidate for diagrams; assess keyboard interaction, save format, extensions and large-document performance before a migration. Not a general vector editor. |
| [Konva](https://github.com/konvajs/konva) | Registry 10.9.1 declares MIT; metadata modified 2026-10-31. | Canvas candidate for visual interaction; would require an accessible non-canvas editing path, structured document model and integration work. Not installed or benchmarked. |
| [Fabric.js](https://github.com/fabricjs/fabric.js) | Registry 7.4.0 declares MIT; metadata modified 2026-10-31. | Alternative object-based canvas candidate; assess serialization compatibility, accessible controls and untrusted SVG/image import before adoption. Not installed or benchmarked; avoid adding it alongside Konva without a clear need. |
| [Three.js](https://github.com/mrdoob/three.js) | Registry 0.187.0 declares MIT; metadata modified 2026-10-30. | Potential future renderer/picking layer only; not a B-rep kernel, constraint solver or CAD system. Not installed for Design Studio. CAD kernel and solver licensing gate remains separate. |

No performance benchmark, compatibility decision or legal approval is implied by this comparison. Responsive UI design requires actual layout and breakpoint semantics, not just scaling a canvas; prototype interactions must remain structured and must not execute arbitrary user code.
